# 사람이 직접 평가하기 (A/B 블라인드)

AI 채점의 한계를 넘기 위한 사람용 평가 페이지입니다. 문제마다 **스킬 없는 답**과 **스킬을 쓴 답**이 무작위로 A·B에 배정되고,
어느 쪽인지는 **모든 평가를 끝낸 뒤**에 공개됩니다.

## 쓰는 법

1. [`index.html`](index.html)을 브라우저로 엽니다(더블클릭, 인터넷 없이 동작).
2. 문제마다 답안 A·B를 읽고 → 더 도움이 된 쪽 선택 → 4개 항목을 A·B 각각 1~5점 → (선택) 한마디.
   - 새로움 / 실행 가능성 / 이해하기 쉬움 / 내 문제에 맞음
3. 6문제를 끝내면 정답이 공개되고 승패·항목별 평균이 나옵니다. **JSON/CSV로 저장**해 두세요.
4. 입력은 브라우저에 자동 저장됩니다(탭을 닫아도 유지). "처음부터 다시"로 지울 수 있습니다.

여러 사람이 각자 평가해 CSV를 모으면 AI 채점과 비교할 수 있습니다. 결과 파일에는 `A_is`/`B_is`(그 문제에서 A·B가 무엇이었는지)와
`winner_is`(skill / base / tie)가 들어 있습니다.

## 내 문제로 평가하기

1. 문제 하나당 폴더를 만듭니다: `eval/human/pairs/<이름>/`
2. 그 안에 파일 3개:
   - `problem.txt` — 문제 원문
   - `baseline.md` — 스킬 **없이** AI가 답한 결과 (그냥 문제만 주고 받은 답)
   - `skill.md` — `skills/idea-flip`을 **따라** AI가 답한 결과
3. `python eval/human/build.py` 로 `index.html`을 다시 만듭니다(`--seed 숫자`로 A/B 배정을 고정할 수 있음).

> 공정하게 비교하려면 두 답을 **같은 모델·같은 조건**에서 받으세요. 되묻지 못하게 하고 가정만 적게 하면 평가가 깔끔합니다.

## 2판 (v2): 더 공정한 비교

1판의 문제를 고친 버전입니다. 근거와 한계는 아래와 같습니다.

| 1판의 문제 | 2판의 방식 |
|---|---|
| 개발 문제가 많고 평가자도 개발 동료 | **비개발 위주 새 문제 8개**(`eval/problems_v2.json`, 개발 1개). 스킬을 다듬는 데 쓰지 않은 문제 |
| 스킬 없는 쪽 문구가 달랐음("뻔한 말 말고" 등이 문제 원문에 섞임) | **두 쪽 모두 같은 단순 요청**("이 문제를 해결할 아이디어를 알려주세요"). 창의성·새로움을 요구하는 말을 넣지 않음 |
| 답이 1개씩이라 운이 큼 | **쪽마다 3개씩** 만들고, 평가자마다 무작위로 하나씩 보여 줌 |
| 길이·형식 차이로 알아보기 쉽고 "이해하기 쉬움"이 불리 | **두 단계로 분리**: ① 아이디어만 같은 모양으로 정리한 목록으로 비교 ② 원본 전체로 쓰기 편함 비교 |
| 정답표가 페이지 소스에 있음 | **정답표 분리**: 페이지에는 무작위 ID만 있고, 정답표는 `keys/`(git 제외)에만 있음. 평가자에게 결과를 공개하지 않음 |

### 순서
```bash
python eval/human/gen_v2.py                 # 답안 48개 생성(스킬 없음/스킬 x 3 x 8문제, 격리 실행)
python eval/human/normalize_v2.py           # 1단계용 아이디어 목록으로 정리
python eval/human/build_v2.py --round 1 --seed 1   # 평가 페이지 + keys/key-r1.json
# 평가자들이 내려받은 JSON을 한 폴더에 모은 뒤
python eval/human/aggregate_v2.py <폴더> --key eval/human/keys/key-r1.json --out summary.json
```

### 알아둘 한계
- 평가 끝나기 전에는 `keys/`, `pairs_v2/`, 빌드된 `index-v2-r*.html`을 저장소에 올리지 마세요(`.gitignore`에 들어 있음). 끝난 뒤 해당 줄을 지우고 올립니다.
- 1단계 목록은 변환기가 "최대 5개"로 정리해서, 카드 4장인 스킬 답은 4개, 스킬 없는 답은 최대 5개가 됩니다. 아이디어 개수 차이가 영향을 줄 수 있습니다.
- 변환은 AI가 하므로 원문의 뉘앙스가 조금 달라질 수 있습니다.
- 평가자가 답의 모양으로 쪽을 짐작할 수 있습니다(2단계 원본 전체는 특히). 완전한 블라인드는 아닙니다.
- 평가자 15명 수준에서는 승률이 65~70% 이상으로 크게 차이 나야 발견됩니다. 작은 차이는 신뢰구간이 넓게 나옵니다.
- 2판 도구(페이지·집계)는 무작위로 눌러 본 시험으로만 확인했고, 실제 평가자 데이터로는 아직 쓰지 않았습니다.

## 알아둘 한계

- **완전한 블라인드가 아닙니다.** 스킬 답안은 고정 카드 형식과 분량(약 2~3배) 때문에 알아보기 쉽습니다.
  길이가 아니라 *내게 쓸모 있었는지*로 판단해 주세요.
- 기본 6문제는 스킬을 다듬는 데 쓴 문제이므로, 스킬에 유리하게 편향됐을 수 있습니다. 새 문제로 해보는 것이 가장 믿을 만합니다.
- 정답표가 페이지 소스에 base64로 들어 있어 소스를 보면 미리 알 수 있습니다(평가자가 그렇게 하지 않는다는 전제).

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 빌드된 평가 페이지(그대로 열면 됨) |
| `template.html` | 페이지 원본(화면·평가 로직) |
| `build.py` | 답안을 읽어 A/B를 섞고 `index.html` 생성 |
| `marked.min.js` | 마크다운 렌더러(marked v12, MIT) — 페이지에 내장 |
| `pairs/` | 내가 추가하는 문제 쌍 |
